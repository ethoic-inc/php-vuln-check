Which PHP versions fix PHP2Shell?

PHP2Shell is two critical remote code execution bugs in the PHP engine (CVSS 9.2) that need no login. PHP's own advisories (CVE-2026-109618, CVE-2026-109619) list every release below the fixed ones. Sansec reports the bugs reach back to PHP 5.4, mainly through Apache mod_php and PHP-FPM.

What it checks

Servers

Every PHP CLI, FPM, CGI and Apache mod_php install, its version and its package changelog.

Docker and Kubernetes

FROM lines, compose files and manifests, with the file and line number.

Whole fleets

Run it on every host over SSH. Nothing is installed on them.

CI pipelines

A GitHub Action and SARIF output put findings in your Security tab.

Frequently asked questions

How do I check if my server is vulnerable to PHP2Shell?

Run php-vuln-check on the server. VULNERABLE means the PHP there is below the fix and has no vendor backport. PATCHED means the version is fixed or the vendor changelog names both CVEs.

Does Debian, Ubuntu or RHEL ship a fixed PHP?

Often as a backport on an older version number, so PHP 8.2.30 on a distro can be safe. The checker reads the package changelog for both CVE IDs before calling a host patched.

Is PHP 7.4 or 8.1 vulnerable to CVE-2026-109618?

Treat them as vulnerable. PHP's advisories only list 8.2 to 8.5, but Sansec reports the bugs reach back to PHP 5.4 and there is no upstream fix for older branches. They are safe only if your vendor's changelog names both CVEs.

Will the checker crash my server?

No. It sends no exploit traffic. On a server it reads files and runs php -n -v and php -i; --no-exec skips even that.

How is this different from other PHP2Shell scanners?

Active scanners probe a host by deliberately triggering PHP memory exhaustion. php-vuln-check reads versions, changelogs and config instead, so it is safe on production and covers images, pipelines and whole fleets. Use both.
